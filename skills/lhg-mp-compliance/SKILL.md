# lhg-mp-compliance：发文合规自查

> 目标：发出去的文章不出事。不出事 = 不被删文、不被投诉、不吃官司。
> 核心纪律：**先跑脚本（机器），再做复核（人）；blocker 不清零，不许说"可以发了"。**

## 1. 何时使用

- 稿件定稿、准备发布前 → 跑全流程（对应 `/mp-audit`）
- 写完初稿想快速看一眼 → 只跑第 2 步（脚本），10 秒出结果
- 改完 blocker 回归 → 只跑脚本确认消失，不用每次全量

## 2. 第一步：跑确定性审计脚本（必做）

用你所在平台执行本地脚本的方式，运行插件自带的审计脚本：

```
python3 <插件目录>/scripts/audit/mp_audit.py --target <稿件文件或目录> [--format json|text] [--fail-on blocker|warning|nit]
```

脚本能力（24 条规则，零第三方依赖）：

| 类别 | 规则 | 说明 |
|---|---|---|
| 错别字 MP-TYPO | 6 条 | 自建高频错别字表：做为→作为、在说→再说、爆 炸→爆炸、园满→圆满、连索→连锁、予盾→矛盾 |
| 违禁词 MP-BAN | 6 条 | 涉政敏感词 / 医疗断言（根治/治愈/特效）/ 金融承诺（稳赚不赔/保本保收益）/ 极限词（国家级/最高级）/ 低俗词 / 联系方式外链 |
| AI 味 MP-AI | 5 条 | 首先其次最后计数 / 综上所述类总结腔 / 值得一提的是类口头禅 / 不仅而且滥用 / 平均句长 |
| 标题 MP-TITLE | 4 条 | 无标题 / 标题超 30 字 / 标题党词（震惊/速看）/ 标题含违禁词 |
| 结构 MP-STRUCT | 3 条 | 长文无小标题 / 超长段落（>500 字）/ 正文不足 800 字 |

- 有 blocker 时脚本以非零 exit code 退出——这是设计，不是 bug。
- `--fail-on` 默认 `blocker`；重要稿件可用 `warning`（更严）。
- 脚本只做"机器可判定"的事：洗稿、事实真假、观点风险，它判定不了，那是第 4 步的事。

## 3. 第二步：分级处理

| 级别 | 定义 | 处理 |
|---|---|---|
| blocker | 发出去会出事：涉政敏感词、医疗断言、金融收益承诺、标题含违禁词 | 必须改（改写/删除），不许豁免，不许为清零改脚本 |
| warning | 大概率是坑：错别字、AI 味信号、标题过长/标题党、长段落 | 逐条修；修不掉的写进报告"已知风险"并说明理由 |
| nit | 洁癖项：个别长句、标点小问题 | 顺手修 |

修一条用脚本复查一条。同一文件的多个 blocker 一次改完，不要修一条跑一次。

## 4. 第三步：人工复核（脚本覆盖不到的）

### 4.1 事实核查
- 人名、机构名、职务：抽查 3 处，确认字没写错（如"宁德时代"不是"宁德市代"）。
- 数字、比例、年份：抽查 3 处，确认可溯源。凡是"我记得好像是"的一律标"待核实"，要么查证要么删掉。
- 政策、法规名称：必须写全称 + 文号/年份，不确定的不写。

### 4.2 洗稿风险
- 核心观点 + 结构：如果与某篇已知爆款"观点相同、结构相同"，即使文字不同也算高风险 → 必须重写结构或换角度。
- 案例/数据：引用他人文章的独家案例必须注明来源；"我朋友"系列的编造案例一旦被扒，账号信用直接归零。
- **判断标准**：把你的文章和疑似原文并排放，找 3 个不同点。找不出来 → 就是洗稿，别发。

### 4.3 引用规范
- 引用公开数据：注明来源（`数据来源：XX 报告，2026`）。
- 引用他人观点：注明出处（`正如 XX 在《XX》中所说`）。
- 截图/图片：确认有版权或已获授权；网络图片注明来源。

### 4.4 敏感题材声明
以下题材必须在文末加声明（1~2 句），缺了就是 blocker（人工项）：

- 医疗健康：`本文仅为科普分享，不构成诊疗建议，身体不适请及时就医。`
- 理财投资：`本文仅为个人观点分享，不构成投资建议，投资有风险。`
- 政策解读：`本文为个人解读，具体以官方发布为准。`

### 4.5 标题党复核
标题承诺必须在正文前 500 字兑现。检查方法：遮住正文只看标题，问"读者点进来期待看到什么？"，再看正文前 500 字给没给。对不上的，要么改标题，要么在前 500 字补兑现。

## 5. 第四步：输出报告

```markdown
# 发文自检报告（YYYY-MM-DD）
## 结论：建议发布 / 不建议发布
## blocker（n）：已修 n，剩余 n
- [规则ID] 文件:行 —— 说明 —— 状态（已修/需人工）
## warning（n）：已修 n，已知风险 n（理由）
## 人工复核：事实 x/3，洗稿（通过/不通过），引用（通过/不通过），声明（已加/不涉及），标题党（通过/不通过）
## 发布 checklist
- [ ] 标题 ≤ 30 字  [ ] 摘要 ≤ 120 字  [ ] 封面图  [ ] 定时发送  [ ] 文末引导
```

报告存为 `drafts/audit-YYYYMMDD.md`。结论"不建议发布"必须写清卡在哪一条。

## 6. 误报处理

脚本词库是启发式，一定会误伤：

1. **判断三问**：这个词在上下文里真的违规吗？规则的本意是什么？按规则改了会不会伤害表达？
2. **确认误报**：在报告"已知风险"区写清理由（如"根治"出现在"根治拖延症"的比喻语境，非医疗断言），并记一笔。
3. **拿不准**：按 blocker 处理，不要直接忽略。**误报的代价是改几个字，漏报的代价是删文封号。**
4. **规则本身有问题**：附最小复现文本提 issue（见第 8 节），不要自己改脚本阈值。

## 7. 高频翻车案例（自查时对照）

下面是公众号最常见的 5 种翻车，每种后面跟"自查时怎么防"：

1. **医疗断言翻车**：养生号写"每天喝 X，7 天根治高血压"→ 被投诉虚假宣传，删文 + 警告。
   防：凡是出现"根治/治愈/特效/包好"，一律改成"可能有助于/有研究表明"，并加医疗声明。
2. **收益承诺翻车**：理财号写"跟着买，年化 30% 稳赚不赔"→ 被认定非法荐股线索。
   防：收益数字必须有来源和时间区间；"稳赚不赔/保本保收益"出现即 blocker。
3. **标题党翻车**：标题"震惊！他一夜之间…"，正文是广告 → 被用户投诉"文不对题"，限流。
   防：按 4.5 节做标题兑现检查。
4. **洗稿翻车**：观点结构全抄爆款，只换了例子 → 原作者挂人，掉粉 + 道歉。
   防：按 4.2 节做"找 3 个不同点"测试。
5. **事实翻车**：把"宁德时代"写成"宁德市代"、年份写错 → 评论区翻车，信用受损。
   防：按 4.1 节抽查 3 处人名机构数字。

**记住**：删文是最轻的代价。医疗/金融/涉政三类，宁可不过审不发，不许带着 blocker 发。拿不准的，截图问有经验的朋友，别自己赌。

## 8. 反模式

- ❌ 只跑脚本不做人工复核——脚本抓不到"观点是抄的"这种问题
- ❌ "warning 太多了，先发了再说"——warning 就是未来的删文理由
- ❌ 为了清零把敏感词换成拼音/谐音——平台一样能识别，还显得你心虚
- ❌ 医疗/理财题材不加声明——这是 blocker，不是可选项
- ❌ 自检报告只写"通过"两个字——没有过程的结论不可信

## 9. 自检与反馈

跑完本 skill 自问：

1. 脚本真的跑了吗（而不是"我觉得没问题"）？→ 没跑不算做。
2. blocker 清零或全部列入"需人工处理"了吗？→ 有遗漏就补。
3. 人工复核 5 项逐项有结论吗？→ 结论要有依据（抽查来源/对比说明）。
4. 敏感题材声明加了吗？→ 医疗/理财/政策三类，缺声明就是 blocker，不能"下次注意"。

标准冒烟用例：对插件自带的 `fixtures/` 跑脚本，确认坏 fixture 的 blocker 全命中、好 fixture 零 blocker（见仓库根 `smoke_test.py`）。

反馈渠道：以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-wechat-article/issues，正文写清"输入 → 错误输出 → 期望输出"。规则误报/漏报请附最小复现文本。
