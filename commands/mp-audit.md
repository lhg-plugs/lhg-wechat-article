# /lhg-wechat-article:mp-audit —— 发文前自检

用户输入在 `$ARGUMENTS` 中：`<稿件文件或目录> [--strict]`。缺省为 `drafts/` 下最新的一篇稿件。
`--strict` 把 warning 也当 blocker 处理（重要稿件/广告法高风险题材建议开）。

按 `lhg-mp-compliance` skill 全流程执行；结论只能是"建议发布"或"不建议发布"。

## 流程

### 1. 跑脚本（必做）
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/mp_audit.py --target <稿件> --format text
```
记下 blocker / warning / nit 的数量与明细（含行号、规则说明）。

### 2. 分级处理
- **blocker**：涉政敏感词、医疗断言、金融收益承诺——必须改掉（改写/删除），不许豁免。
- **warning**：错别字、AI 味信号、标题过长/标题党、长段落——逐条修；修不掉的写进报告"已知风险"。
- **nit**：顺手修。
- 修一条用脚本复查一条；**不许**为清零改脚本规则或阈值。

### 3. 人工复核（脚本覆盖不到的）
- [ ] 事实核查：人名/机构/数字/政策名，抽查 3 处可溯源（给出来源）
- [ ] 洗稿风险：核心观点与结构是否与某篇爆款雷同（凭经验判断，如雷同必须重写结构）
- [ ] 引用规范：引用数据/他人观点是否注明来源
- [ ] 标题党复核：标题承诺与正文是否相符（文不对题是取关主因）
- [ ] 敏感题材：涉及医疗/金融/政策解读的，确认已加"仅供参考/不构成建议"类声明

### 4. 输出报告
```markdown
# 发文自检报告（日期）
## 结论：建议发布 / 不建议发布
## blocker（n）：已修 n，剩余 n
## warning（n）：已修 n，已知风险 n
## 人工复核：x/5 通过
## 发布 checklist：标题□ 摘要□ 封面图□ 定时□
```
报告存为 `drafts/audit-YYYYMMDD.md`。结论"不建议发布"时必须写清卡在哪一条。

## 红线提醒

- 本命令只做"建议"，**不自动发布**。发布（公众号后台操作 / 发布工具调用）永远由用户亲手完成。
- 脚本词库是启发式：误报按 warning 处理并记录，不许直接忽略 blocker；拿不准的按 blocker 处理。
